# Image credits

Every file under `assets/images/` right now is a **locally generated, on-brand
placeholder** (a gradient + one icon from `assets/icons/sprite.svg` + the
slot's subject as a caption) — not a photograph, and not sourced from the
internet. They were generated by a one-off script because this build
environment's network policy blocks the real photo sources (Wikimedia
Commons, Unsplash, Pexels, etc. — only GitHub domains are reachable here), so
`tools/fetch-images.mjs` could not run.

**These carry no licence or attribution requirement** — they are original,
programmatically generated shapes, safe to ship as-is for as long as needed.

**To replace them with real photographs**, either:

- Run `node tools/fetch-images.mjs --force` from a machine or CI runner that
  *can* reach `commons.wikimedia.org` — it resolves every slot in
  `tools/images.manifest.json` to a freely licensed (CC0 / public domain /
  CC BY / CC BY-SA) photograph, downloads it to `assets/images/<key>.jpg`,
  regenerates `assets/js/data/images.js`, and writes this file with the real
  per-photo credit table (title, author, licence, source). The `--force`
  flag is needed because it only skips a slot that already has *both* a file
  **and** a credits entry — these placeholders have no credits entry, so a
  plain `node tools/fetch-images.mjs` (no flag) will already pick them up
  and overwrite every `.svg` with a real `.jpg`, in the same slot.
- Or drop the business's own photograph in at `assets/images/<key>.jpg` (or
  any extension) and point that slot's path in `assets/js/data/images.js` at
  it directly — `imageSrc(key)` just returns whatever path is in that map.

The slot key never changes either way, so nothing else in the codebase needs
to change when the real photograph arrives.
