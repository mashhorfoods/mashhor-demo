01

Direction & inheritance

The brand already has a complete system: a single-blue palette derived from the logo, an approved Arabic type pairing, a radius ramp, a shadow set and accessibility guardrails. Stage 03 does not restate it and does not fork it. It narrows it for interface density and extends it only where an operational product needs something a marketing site never did.

PaletteSingle blue #4975BA + navyIdenticalUnchanged. No second palette exists in this document.
Type pairingIBM Plex Sans Arabic + CairoIdenticalPlex Arabic carries UI and headings; Cairo carries reading copy. Latin here is IBM Plex Sans — the same superfamily, so annotation never introduces a third voice.

What "premium" means in this product

Not ornament. A dispatcher looks at this screen for hours, so the premium signal is restraint: one accent colour, one shadow that is almost invisible, generous row height, a table that stays readable at the eleventh row, and no gradient, glass or decorative illustration anywhere. Every visual device below is spent on hierarchy or state — never on interest.

The greyscale proof

Reduced to luminance, four of the five status hues land within twelve levels of each other — blue 113, amber 126, green 106, slate 101. Colour alone therefore cannot carry status in this product, which is why every badge in §13 pairs its word with a distinct icon shape. The greyscale row there is the test.

Eleven roles, two Arabic faces, three weights. IBM Plex Sans Arabic carries structure — titles, labels, navigation, tables, numbers — because its even rhythm holds at small sizes in a dense row.   • Page margins — 16px mobile, 24px tablet, 32–64px desktop, fluid between.
  • Card padding — 20px, dropping to 16px on mobile. Stat cards keep 20px so the figure never crowds its label.
  • Table rows — 12px block padding gives a 48px row: countable at a glance, and still a comfortable touch target.
  • Form fields — 8px label-to-control, 20px between fields. Related fields group at 12px, and the tighter gap is the only thing signalling the group — no boxes inside boxes.

One ramp, no exceptions. A control is 8, a container is 12, an overlay is 16, and anything that states a status or a count is a pill. Nesting always steps down: a 12px card holds 8px controls, never the reverse.

08

Depth

Four levels, all built from one shadow colour — the ink at low opacity, so shadows read as the page's own neutral rather than as grey haze. Borders do most of the separating; shadow only signals which layer something is on.

--sh-card --sh-raised --sh-dropdown --sh-modal
--sh-card
resting cards, rows
--sh-raised
hovered card, header
--sh-dropdown
menus, toasts, popovers
--sh-modal
modals, drawers
  • Borders separate; shadows elevate. A card on the page ground gets a 1px divider and almost no shadow. Only things that float above the page — menus, toasts, modals — carry real depth.
  • No gradients, no glass, no glow. The sidebar is flat navy; the header is white with a hairline.
  • The scrim is rgba(30,39,51,.42) — the ink, not black, so the dimmed page keeps its colour temperature.
09

Icons

One outline set, drawn for this product: 24px canvas, 1.75px stroke, round caps and joins, rendered at 20px in navigation and buttons and 16px inside badges and dense rows. Nothing decorative, nothing filled except the deliberate solid dots that make three status marks distinguishable in greyscale.

.i24 canvas · 1.75 stroke · currentColor

RTL rule: only direction mirrors

Mirror anything that points — arrows, chevrons, the return control, progress direction. Never mirror anything that represents an object or a reading of the world: the clock, the phone, the calendar, the checkmark, the person. A mirrored checkmark reads as a mistake; a mirrored clock reads as a broken clock.

Icons in navigation and buttons take currentColor, so an active or disabled state changes the label and the icon together and they can never drift apart.

Buttons

Four variants. Exactly one primary per screen region — if two things look primary, neither is. Minimum height is 40px on pointer devices and 44px on touch, matching the brand's --min-tap.

.btndefault · hover · focus · pressed · disabled

Primary — the one main action

Secondary — supporting action

Ghost — low emphasis, and every table row action

Destructive — outlined at rest, filled only on commitment

Sizes — 32 / 40 / 44px, plus the square icon button

  • Destructive is outlined, not filled. A red block is the loudest thing on a screen; at rest it should not outrank the safe primary action. It fills red only on hover and press — at the moment of commitment.
  • Icons lead the label in RTL (to its right) and are always 16px against 15px text.
  • Disabled buttons keep their shape and never carry a tooltip as their only explanation — if a control is unavailable, the reason is on the screen (Stage 02 §16).

  • The label never becomes a placeholder. Placeholders are examples of the expected value, and they disappear exactly when the user needs the label most.
  • Required is a word, not an asterisk — (مطلوب) beside the label.
  • Errors carry an icon as well as red, sit under their field, and are tied to it for assistive technology.

تعذّر تغيير الحالة

Loading — first load is a skeleton, an update is a bar

جارٍ التحميل…
  • Success is a toast; failure is an alert. A success can be missed without cost, so it self-dismisses. A failure needs a decision, so it stays until it is resolved.
  • Every error names the recovery. "Your data is still in the form — try again" is the message; a code is not.
  • Skeletons hold the real shape of what is arriving, so nothing shifts when content lands. A list already on screen dims and shows the bar rather than being replaced by skeletons.
  • Feedback is announced to assistive technology without moving focus (Stage 02 §23).

Decisions & handoff

Decisions taken here, and why

  • Light theme only. The brand has no approved dark palette, and deriving one would be a second identity — the one thing §02 of the brief forbids. If long-shift comfort later argues for a dark mode, it is a brand decision first and a system change second.
  • Cancelled is neutral, not red. Red is reserved for errors and destructive confirmation.
  • Confirmed takes navy. It keeps the lifecycle's three "positive" states — new, confirmed, completed — distinguishable from each other rather than three shades of agreement.
  • The radius ramp stepped down one notch from the website's, for control scale. This is the only geometry that differs from the site, and it is proportional rather than arbitrary.
  • No dashboard, requests or content page is designed here, per §23 of the brief. Every specimen above is a component shown in isolation; none is assembled into a screen.
