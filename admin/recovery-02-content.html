What the inspection found

The module did not exist — no page, no table, no route, and no path from anything typed in the dashboard to the published site. What the inspection also found is the part worth reading twice: three of the six approved content areas do not exist on the public site either.

And there is no English copy anywhere. index.html is lang="ar" and carries one language. §11's separation is implemented and enforced by the primary key; there is simply nothing on the other side of it, and §05 forbids inventing any.

What that means for §08 and §09

The brief asks for FAQ and testimonial management, and forbids fabricating entries in the same breath. Both editors were built and both work. Neither was seeded, and the module says on the page that those two areas have nowhere public to go until a section is approved for them. Adding sections would be adding unapproved sections, which §33 forbids.

02

Reaching a static page

The public site is one static HTML file. That is a deliberate property of this project — it is why the page performs the way it does — and §33 forbids redesigning it. Two of the three obvious ways to make content dynamic were therefore off the table: turning index.html into a per-request template, and hydrating the page from an API on load. Both change what the page is.

The third way is to rewrite the file. Every editable region is wrapped in a pair of HTML comments:

One region, in the shipped page

<!--aun:about.lead-->…the approved copy…<!--/aun:about.lead--> 25 pairs, about 1.2KB. Invisible, nothing in the accessibility tree, no effect on layout or style. build.js keeps them while stripping every other comment — 16.2KB of design log still comes out.

Publishing replaces what lies between one pair and reads nothing outside it. That is §20 made structural rather than careful: editing the About lead cannot disturb a service, a FAQ or the contact address, because the write is bounded by the markers.

Save, then publish — two deliberate acts edit→ validate→ database→ activity log→ publish→ temp file→ rename→ index.html

The write is atomic — a temporary file beside the target, then a rename — so a failure halfway through leaves the previous page intact rather than a half-written one. And saving and publishing are separate buttons on purpose: an administrator can draft several edits and make them public in one deliberate act, and a save that fails never claims otherwise.

Getting there took two corrections worth recording, because both would have shipped as silent corruption:

R2-01

The services end-marker swallowed its siblings

Cause
The region was bounded by the closing </div> of the slides container, which is not where the slides end — a decorative progress list and the scroll track sit between the last </article> and that tag.
Effect
The first publish deleted both. The round-trip check caught it immediately, because a lossless mechanism does not remove twenty lines.
Fix
Bound each list region by its own last item rather than by a closing tag, so anything that follows the items stays outside the region by construction.
R2-02

Three regions carry markup, and escaping destroyed it

Cause
The phone number is built from &nbsp; runs, the address has a <br>, and the closing sentence has a styled <span>. Escaping every region turned all three into visible source.
Fix
Classify the regions. Twenty are plain text and are escaped; three go through an allow-list. §06 below.

05

What it refuses to do

Three refusals, each one a rule in the brief that a more accommodating implementation would have quietly broken.

§06 §07 — the approved set

لا يمكن إضافة سجل جديد

The six features and seven services are approved content. POST /api/admin/content/item/new returns 409 for those collections — not a hidden button, a refusal at the endpoint. Editing and reordering them is the whole job; inventing an eighth is not.

§08 §09 §26 — the empty state

لا توجد أسئلة شائعة

Nothing was seeded into the FAQ or the testimonials. Filling an empty state with plausible content is the single easiest way to put fabricated customer quotes on a real company's website, and the brief forbids it three separate times.

§05 §11 — the other language

English — لا يوجد محتوى

The switch is present and disabled, not hidden: an operator should be able to see that the separation exists and that there is nothing on the other side of it yet. Storing an English title is proved not to touch the Arabic one, and publishing is proved to write Arabic.

06

Markup that had to survive

Twenty of the twenty-three text regions are plain text and are escaped on the way out. Three are not, and escaping them would have rewritten approved content:

  • The phone number — &nbsp; runs that hold the grouping together.
  • The address — a <br> between the street and the district.
  • The closing sentence — a <span class="contact__aside-tag"> around the tagline.

Those three go through an allow-list, not a blocklist: everything is escaped first, then exactly the constructs the approved page already uses are restored — <br>, <b>, <strong>, <em>, and a <span> carrying nothing but a class. Unbalanced closes are dropped, so a rejected tag cannot close a span the page opened around it. A <script>, an onclick= or a javascript: URL survives none of the twenty-three fields — and the suite proves it by storing one, publishing, and reading the live page back.

09

What this still is not

  • The FAQ and the testimonials have nowhere public to go. Not an oversight — adding sections for them is adding unapproved sections. The editors work and the records persist; approving a section on the public site is a decision, not a bug fix.
  • English is empty. The separation is real and tested. There is no approved English copy to load, and this stage was not going to write any.
  • Service ordering regenerates a pinned-scroll component. The slides are re-emitted with recomputed indices and it is verified to render, but a heavily reordered showcase is worth a look on a real device before it goes live.
  • Publishing needs write access to index.html. On Hostinger the PHP user owns public_html, so it works. The overview reports whether it is writable and disables the button with an explanation when it is not — it never fails silently.
  • This is not a page builder. Deliberately. Structured content, fixed regions, no layout editing — §34.

Where this leaves the system

  1. التقارير is the last unbuilt module. Everything else in the approved navigation now exists.
  2. Three modules still render seeded data in the browser — الخدمات، الوسائط والأصول and الإعدادات. Their endpoints are live and protected; the pages have not been switched over. الخدمات is now editable through المحتوى either way.
  3. Deploy and run php bin/seed-content.php, then edit one line and press publish. That is the shortest path to knowing the mechanism works on the real host.
